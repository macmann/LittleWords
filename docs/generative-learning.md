# Generative Learning UI

Enable `GENERATIVE_UI_ENABLED=true` after `npm run db:migrate`. The home adventure button opens the new renderer; ordinary cards, missions, parent tools, navigation and account controls retain their existing behavior. The adventure entry retains the parent gate; offline entry requires the parent area to have been unlocked while connected. Disable the flag for rollback. No AI credentials are required: deterministic local lessons are the default. Existing child-level AI planning consent is also required before calling a provider.

Optional server variables: `GENERATIVE_AI_ENDPOINT` (full chat-completions endpoint), `GENERATIVE_AI_API_KEY`, `GENERATIVE_AI_MODEL`. OpenAI, DeepSeek and compatible self-hosted providers use the same adapter. Never expose these variables to clients. Provider requests have an eight-second timeout, bounded response size, no redirects, and strict response validation. No child names, identifiers, photos or custom vocabulary enter provider context. Context includes approved vocabulary IDs, language preferences, optional age and measured mastery. All content text and media resolve through the existing catalogue and audio service.

`lib/generative/domain.ts` is the platform-independent contract and planner. Zod objects are strict, with no free-form presentation text or code fields. Vocabulary references are existing Concept IDs; those IDs resolve localized text, images and audio on each platform. Lesson JSON contains semantic theme, palette, reward and activity enums only. Version `1.0` is required; unsupported versions are rejected. Future additions must preserve existing enum meanings or introduce a new version. Browser APIs are confined to the web renderer. A native renderer can implement the same contract with native images and audio.

Supported activities: learn_card, image_choice, listen_choice, match_pairs (image to word), speak_repeat (explicit “I said it” fallback), drag_drop and story_scene. Matching uses taps rather than dragging. Drag_drop provides a large basket target with an equivalent tap interaction for touch and keyboard users. Story_scene places approved objects using a fixed renderer grid and a “Find” prompt. Both use approved choices only. Speech recognition remains an optional adapter with the self-reported fallback. All nine themes, five palettes and six finite celebration styles are approved renderer tokens. Rewards use a fixed symbol and positive completion message, with no engagement loop or randomized prizes.

Authenticated endpoints:

- `POST /api/v1/lessons/generate`: `{ "language": "EN", "schemaVersion": "1.0" }`; returns a GenerativeLesson. Language must be enabled on the caller's child profile. An unfinished lesson created within the previous minute is reused.
- `GET /api/v1/lessons/:lessonId`: returns an owned, supported lesson.
- `POST /api/v1/activities/:activityId/result`: `{ "lessonId": "...", "selectedIds": ["approved-id"], "responseTime": 1200 }`. Use an empty array for introductions and self-reported speech. Pair answers list the selected word ID for each picture in the activity's wordIds order. The server validates choices, ordering, ownership and correctness. Picture matching uses only reviewed alternatives for that word. First submission wins; retries are idempotent.
- `POST /api/v1/lessons/:lessonId/complete`: requires every activity result. Repeated completion is safe.
- `POST /api/v1/lessons/:lessonId/events`: accepts authenticated `activity_started` and `reward_shown` events; activity IDs and completion state are checked.

Mutation routes use the existing authenticated account and same-origin protection. IDs are assigned by the server. Persistent records are child-owned with cascade deletion. Bootstrap exposes an unfinished lesson and its next activity so the child can resume. Completed generative sessions and their explored activities contribute to the existing progress totals. Only measured answers contribute to mastery, independently per language; introductions and self-reported speech do not imply mastery. Three measured attempts are required before increased difficulty. Children below four retain difficulty one. Novelty rotates themes, palettes, rewards and activity patterns without replacing needed word repetition.

With approved vocabulary already loaded in the open application, offline startup and backend generation failure use the same local schema and renderer. A cold offline navigation uses the existing standalone PWA offline activity; account and bootstrap data are intentionally never cached. Offline practice explicitly says progress will not be saved; this MVP does not promise offline synchronization. If connectivity is lost during a server lesson, the answer remains retryable without advancing or inventing saved progress. A local lesson cannot be uploaded as a trusted server lesson.

The development-only inspector shows lesson JSON, version, difficulty, themes, palettes, sequence and rewards. Production builds omit it. Internal server logs emit allowlisted learning events without child personal information. No external analytics service is used.

Validation: `npm test`, `npx tsc --noEmit`, `npm run build`. Live API integration additionally requires migrated PostgreSQL and an authenticated account. Unit tests cover strict validation, provider failures, deterministic sparse/offline generation, measured difficulty and presentation novelty.

In the managed development environment, the Prisma engine download host is blocked. Client types were generated using Prisma’s bundled WASM schema tooling and the client generator with no engine download; `tsc --noEmit` and `next build --webpack` passed. The deployment build should still run the normal `npm run build` with engine access. No migration or live database integration was run in this environment.
